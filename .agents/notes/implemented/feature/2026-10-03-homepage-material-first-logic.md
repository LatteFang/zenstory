# Agent Note: 首页按“材料 → 路径 → 工具 → 安装”组织下一步

Status: implemented（2026-10-03 用户确认上线；视觉沿用 [手稿到世界](2026-10-03-homepage-manuscript-to-world.md)，本 note 只管页面逻辑、CTA 落点与信息密度）

## Problem

v6 首屏用 Novel to Game 的《西游记》单一案例证明“做出作品”，但旁边的主按钮“找到创作起点”把人送进 `/guides` 十类全目录，首屏唯一的命令又是 Oh Story 的安装，备注还提示 `/story-setup`。被游戏案例说服的人不知道下一步是复现游戏、学写作、装哪个 skill，还是进入浏览器工作台。段落顺序是 演示 → 选工具 → 材料路径 → 知识库，新用户还没确定路径就先面对仓库选择。知识层的“更多”链接四层都叫“继续查找”，技法层落在只有分镜与 AI 视频的分类，排错层落在术语表。

## Decision

段落顺序为 真实演示（`#examples-h`）→ 创作路径（`#start-h`）→ 工具与使用环境（`#choose-h`）→ 知识库（`#guides-h`）→ 项目关系（`#model-h`），锚点与 URL 不变。每段只回答一个问题：成果长什么样、手上的材料怎么走、这一步用哪个工具在哪里用、遇到问题去哪查、项目怎么连起来。

首屏只有一个主行动“从你手上的材料开始”，指向 `#start-h`，首屏不放安装命令。舞台图说为案例提供同 owner 的下一步“用你的小说做一个：Novel to Game 安装与上手”，指向 `/novel-to-game#start-h`（安装命令、入口命令与指南）；措辞不暗示一键重现该游戏，因为该案例的设计文档经过作者多轮修订。首屏备注说明环境关系：创作 skill 在已用的 Agent 中运行，只写小说可用独立的网页工作台；宿主列表标明“各包支持范围不同”。演示段末尾加一条指向 `#start-h` 的下一步。

`content/home-reading.json` 的每条路径带第 8 个字段：起步工具（项目 slug 列表）。生成器校验工具存在，且路径中按顺序的步骤（#02 只算第一步）都属于所列工具，否则构建失败。路径卡底部显示“起步工具”，链接到工具表对应行 `#tool-<slug>`；#02 的两个改编分支卡显示各自工具（取自文章 owner）。#02 仍是先导入续写、再任选短剧或游戏。路径 01 第一步、路径 03 三步的标签改成与落地文章一致（03 第三步标为可选）。

工具行带 `id="tool-<slug>"`；有安装命令的四个 skill 包链接“安装与上手” → `/<slug>#start-h`，DSH 与网页工作台链接项目页。“在哪里使用”组加一段说明：四套 skill 装进已用的 Agent；DSH 是 DeepSeek Harness 插件，内置这四套；网页工作台是独立的小说写作产品，短剧、游戏与解说用对应 skill 包。知识层每层有自己的“更多”标签与落点（第 7 个字段）：入门 → `/guides/getting-started`，完整工作流 → `/guides#learning-paths`，技法与模板 → `/guides#browse-topics`，排错与参考 → `/glossary`（“查术语表”）。收尾带的 Agent 行动改为回到 `#choose-h`。关系图的“小说”节点不再列 DSH，小说只连到短剧与游戏，解说视频由单独的“视频素材”节点进入；首屏说明与 SEO description 同样写成“小说改成短剧或游戏；已有视频素材做成解说”。项目页“你需要什么”里的“或在浏览器里”只在写小说的项目（`WRITING_ENTRIES`，目前是 Oh Story）出现，并注明“仅限小说写作”，短剧、游戏、解说与 DSH 页不再把网页工作台列为替代。

密度按“每节只说自己那件事”收紧：舞台图说只留一行案例标题（《西游记》→ 可玩游戏）和三个短行动（开始改编 → `/novel-to-game#start-h`、案例源码 → 固定提交的案例目录、更多演示 → `#examples-h`），回目与公版来源改写在舞台原著链接的 `title` 上；首屏下方的环境说明、项目数/MIT 句子和 9 个宿主名删除（宿主在 /projects，环境在工具区一句话，MIT 与星数在收尾 facts）。演示段导语不再逐项列媒体类型和“不冒充同一故事”的说明，五张卡的描述各留一句新信息。工具表第三列改用 `home-reading.json` 的 `tools` 短说明（产出什么），完整 tagline 留在项目页；环境说明压成一句。知识区去掉 intro 导语。收尾去掉“创作 / 改编 / 编排”三列（仍在 /projects），只留关系图、一句图说、两个行动与 facts。

## Alternatives considered

- **首屏保留命令，但换成与案例对应的 Novel to Game 安装**：最强的理由是被游戏打动的人一步就能复制命令。没有采用，因为首屏主张面向所有创作者，单一游戏命令会把写网文的主要读者引到错误工具；而且光有命令不够，还需要宿主与入口命令，项目页的“三步开始”更完整。
- **首屏主按钮保留 `/guides`，只改文案**：最强的理由是知识库是站内最大的内容资产。没有采用，因为 `/guides` 的完整路径里没有游戏路径，与首屏案例对不上；材料路径就在同一页，更短。
- **在工具表每行直接放可复制的安装命令**：最强的理由是安装一步到位。没有采用，因为会明显加重已获认可的表格视觉；各包的宿主、入口命令也不同，项目页的安装段更准确。
- **技法层保留 `/guides/ai-video`，只把标签改准**：最强的理由是落点更具体。没有采用，因为这一层第一项是小说人物对白，按创作任务浏览才覆盖整层。

## Consequences

- 首屏、看完案例、进入路径、从知识库返回这四个时点都有明确的下一步；路径到工具、工具到安装都可以点到。
- 首页不再出现任何安装命令；Agent 用户需要多点一次（工具行 → 项目页安装段）。
- 首屏下方不再展示宿主名单，首页上“能在哪些 Agent 里用”只剩工具区一句举例；想看完整宿主要去 /projects 或项目页。
- `home-reading.json` 新增 `tools`，六个项目缺一条短说明时构建失败；只清空路径与知识层的测试夹具保留真实的 `tools`。
- `home-reading.json` 的路径与层级继续用位置数组，新增字段只能靠位置读取；生成器校验可以防止漏填。
- 已知但未在本轮处理（来自只读审计，本轮未逐项复核）：写作演示的方法页 `outline-to-chapter` 只讲章节技法，不讲安装与文件落点（更贴切的 `claude-code-novel-writing` 是 article，测试夹具会替换 article 库，展示方法目前只能指向 guide）；项目页“你需要什么”对各包列出全部 9 个宿主；Video Recap 的安装命令可能与上游 README 不一致；`/guides` 的完整路径没有游戏路径。它们属于项目页或知识库，不在本轮首页范围内。
